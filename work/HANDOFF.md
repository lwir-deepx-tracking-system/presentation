# 발표자료 재구성 인계

2026-11-19 갱신. 대화에서 정리한 사용자 요구사항과 현재 작업 상태. 새로 만들거나 리팩터링할 때 이 문서를 먼저 읽는다. 이후 사용자의 수정 지시가 있으면 그 지시를 우선하고 관련 기준 문서도 함께 갱신한다.

## 발표 방향과 분량

- 최근 사용자 의견: 예비자료보다 본문 보충이 중요하며, 개선마다 숫자 두 개와 화살표를 반복하는 구성만으로는 설명이 애매하다. 단계별 문제·방법·결과·채택 판단을 따라 설명하고 그래프를 근거로 사용한다. 마지막에는 서로 다른 결과의 범위를 함께 정리한다.
- 보고서처럼 많은 설명을 읽게 하는 자료보다 **화면의 그림과 도표 순서를 따라 말할 수 있는 발표자료**가 필요하다.
- 발표자가 긴 대본을 모두 외워야 하는 구성을 피한다. 문제·방법·결과를 장별로 나누고 말할 단서를 화면에 둔다.
- 20분이라는 이유로 슬라이드 수를 14장이나 18장으로 제한하지 않는다. 사용자는 설명 단계가 나뉜 많은 슬라이드를 선호한다.
- 현재 B안은 본문 32장과 예비 20장이다. 장수 자체가 고정 요구사항은 아니다.
- 현재 시간 배정은 설명 17분 + 데모 자리 3분이다. 실제 영상과 낭독 리허설 후 조정해야 하며, 목표 20분을 실제 측정 시간처럼 표시하지 않는다.
- 상세 실험·수치·코드 설명은 대본·출처·예비자료에 보존한다. 단순히 본문 문장을 삭제해 발표자가 외울 내용만 늘리지 않는다.

## 시작 순서

**표지 → 팀 소개 → 프로젝트 소개** 순서다. 팀 소개 다음에는 청중이 프로젝트의 목적과 전체 동작을 이해하도록 소개한다. 운용 화면이나 조작 설명부터 시작하지 않는다.

## 표지

- 상단에는 LIG D&A 로고만 둔다. 별도 슬라이드 제목과 상단 구분선은 없다.
- 본문에는 다음 정보를 표시한다.
  - 프로젝트: **DEEPX NPU를 이용한 LWIR 표적 추적 시스템 구현**
  - 팀명: **5팀 올빼미**
  - 팀원: **윤오름 · 김재남 · 윤관 · 정하건 · 홍정호**
  - 멘토: **천준호 선임연구원** — 기존 팀 자료에서 확인한 표기.
- 표지는 다섯 명 이름을 한 줄에 나란히 표시하고, 윤오름 이름에 팀장 직책을 붙이지 않는다.
- `찾고·이어가고·따라가다`, `쫓아가다` 같은 슬로건 대신 공식 프로젝트 제목을 사용한다.
- 표지 이미지는 실제 **하드웨어 사진**을 넣을 예정이다. 시연 화면·녹화 재생 캡처로 대체하지 않는다.
- 현재 사진은 미수령 상태다. `B/assets/hardware-photo.jpg`를 추가하고 재생성하면 반영된다.

## 팀 소개

- 표지 다음 장에 둔다. 실제 팀원 사진 다섯 장을 나란히 사용한다.
- **윤오름에만 팀장 배지**를 표시한다. 표지의 이름 표기와 구분한다.
- 역할은 각자 두 줄로 간결하게 표시한다. 주요 담당 제목과 세부 업무 목록을 반복해 나열하지 않는다.

| 팀원 | 첫째 줄 | 둘째 줄 |
|---|---|---|
| 윤오름 · 팀장 | 시스템 설계 · 통신 | GUI · 짐벌 제어 |
| 김재남 | Runtime 구현 | 멀티스레드 파이프라인 |
| 윤관 | 적외선 모델 학습 | 경량화 · 최신 모델 조사 |
| 정하건 | 추적 알고리즘 | 성능 검증 · 개선 |
| 홍정호 | Runtime 최적화 | NPU · 추론 가속 |

- 상세 업무는 [team-roles.md](B/team-roles.md)에 보존한다. 개발환경·병합·리팩터링·계측·촬영 지원 등을 지운 성과로 취급하지 않는다.
- 원래 제공한 윤오름의 Qt 앱 개발 기여와 최종 데모 GUI를 혼동하지 않는다. 팀 소개는 기술명을 덜어낸 위 요약을 사용한다.
- 김재남과 홍정호의 파이프라인·최적화 관련 기여가 일부 겹친다고 한 사람의 업무를 다른 사람에게 몰아주지 않는다.

## 일반 슬라이드 제목과 헤더

- 제목은 **짧은 명사형 한 줄**, **LIG 블루**로 통일한다. 예: `운용 화면`, `시스템 구성`, `검출 성능 비교`.
- 설명문·질문·주장형 문장을 제목으로 쓰지 않는다.
- 제목 위에 작은 분류명·섹션명을 반복하는 이중 헤더를 만들지 않는다.
- 로고 오른쪽 끝은 상단 구분선의 오른쪽 끝과 맞춘다.
- 로고 크기는 제목과 동일한 픽셀 높이로 키우지 않는다. 현재 제목 50px, 로고 높이 34px이다.
- 제목의 **실제 글자 영역과 로고의 세로 중심**을 맞춘다. 박스 아래쪽을 맞춘 것만으로 정렬을 판단하지 않는다.
- 제목과 로고를 선에 붙이지 않는다. 구분선이 밑줄처럼 보이지 않게 충분한 여백을 둔다.
- 현재 제목 아래 패딩 22px, 로고 아래 여백 33px이다. 이는 현재 B안의 구현값이며 새 레이아웃에서는 시각적 정렬과 여백을 우선해 확인한다.
- 현재 제목 색상 토큰은 `--blue: #002f6d`다.
- 예비자료도 같은 헤더 기준을 적용한다. 표지에만 별도 예외를 둔다.

## 하단

- 오른쪽의 `02 / 32` 같은 **페이지 표시만** 둔다.
- `확정 전 초안`, `5팀 올빼미 · LWIR 표적 추적`, 기타 상태·프로젝트 문구를 넣지 않는다.
- 하단 구분선과 출처 링크 행도 표시하지 않는다. 출처는 문서·대본에 보존한다.
- 실제 영상 여부나 실험 조건처럼 해석에 필요한 본문 캡션까지 지우는 지시는 아니다.

## 결과 그래프

- 숫자 두 개 사이에 화살표만 놓으면 변화가 잘 보이지 않는다. 전후 비교는 **그래프 + 실제 값 + 변화량**을 함께 사용한다.
- 현재 10·11·15·16·19·23번이 막대그래프로 정리되어 있다. 새로 순서를 바꾸면 장 번호도 갱신한다.
- 같은 지표는 같은 축으로 비교하고, 막대는 0부터 시작한다. 작은 차이를 부풀리기 위해 축을 자르지 않는다.
- 단위와 지표 방향을 표시한다. AP·IDF1 차이의 `%p`와 상대 감소율 `%`를 구분한다.
- 개선뿐 아니라 호출시간 증가·가로 뒤처짐 악화도 보여준다. 다른 단위·다른 시험은 그래프를 분리한다.
- 실제 연속 기록이 있으면 학습곡선을 쓴다. 전후 두 값으로 가상의 시간 경과를 그리지 않는다.

## 요구사항과 성능 해석

- 시간: 30Hz 목표와 약 33.3ms의 입력 주기를 설명하고, 처리량과 같은 프레임의 경과시간을 구분한다.
- 검출: 정한 거리 범위에서 객체를 검출해야 한다. 거리 상·하한과 통과 기준은 확정 전이다.
- 추적: 선택한 ID의 유지·가림·재등장을 확인해야 한다. 유지 시간·허용 끊김 등의 수치 기준은 확정 전이다.
- 제어: 선택한 물체를 2축 짐벌로 추종하고 수동 개입·정지를 확인한다.
- 운용: PC GUI에서 현재 영상·선택·상태를 확인한다.
- 모델 호출, 서버 결과, 화면 표시, 실제 모터 반응의 시간을 같은 숫자로 설명하지 않는다.
- 별도 Runtime 재생 부하 시험이나 실물+가상 표적 시험을 최종 실제 사람 추종 성능으로 확대하지 않는다.

## 최신 팀원 자료 반영

- **11월 19일 afa734f의 윤관 자료를 본문에 보충했다.** 08–11은 현장650장 상체 E10·AP/재현율·추가학습 대조·보류, 18–19는 두 NPU 동시 타일과 실카메라 서버 지연, 20·24는 상체 추적/조준과 전신 표시 분리, 31·32는 측정 구간과 결과 지도다. 본문32장·총20분 목표를 유지했다.
- E10은 공용E2→현장650장→10epoch의 별도 갈래다. OTP2 934장에서 박스 AP36.04→46.28%, 재현율71.70→69.09%. 과거 FLIR s/m 결과와 직접 비교하지 않는다.
- 추가3epoch 대조·시간손실 AP40.23/40.21%는 시작46.28%보다 낮다. 둘 다 하락해 시간손실만을 원인으로 단정하지 않으며 운영 교체를 보류했다.
- 새 지연은 모델뱅크 별도 서버의 실카메라 약30FPS·각65초 결과다. 수신→추적완료 p95 40.47/25.71ms, 동시 타일 큐 버림1장·순서오류0. C++ Runtime 재생 부하·최종 데모 종단 성능과 구분한다.
- 전신 범위는 표시 전용이며 ID 매칭·평가·짐벌 조준은 상체 추적 좌표를 사용한다. 새 재생 이미지 두 장은 서로 다른 프레임이며 전후 ID·성능 비교로 쓰지 않는다. 별도190개 표본은 모두 발목 관측으로 하체 가림 성능은 미평가다.
- 새 근거는 B/sources/latest-20261119/manifest.json에 커밋·해시로 보존했다. 이번 요청은 B안 보충이며 개인 자료·팀원 원본·A안은 수정하지 않았다.
- 사용자는 최신 팀원 발표자료를 근거로 믿고 수정하도록 승인했다.
- `7249d7b`까지의 pull에서 실질 변경은 정하건 v3 추가와 구버전 제거다. 김재남·윤관·홍정호 자료는 이 pull 구간에서 바뀌지 않았다.
- 정하건 v3의 3종 C++ 추적기와 PC–Runtime TCP 선택·변경, Accepted/Completed·프레임 경계 교체·생성 실패 시 기존 추적기 유지가 최신 발표 근거다.
- PC 비교: OC-SORT HOTA59.1·IDF1 66.7%·IDSW531, BoT-SORT HOTA60.7·IDF1 67.5%·IDSW566. 기본 추천은 BoT-SORT, 가림 장면은 OC-SORT. 모든 지표에서 BoT-SORT가 앞선다고 말하지 않는다.
- ByteTrack 2,964회는 Orange Pi 결과다. PC의 두 추적기와 동일 하드웨어 전후 비교로 묶지 않는다. 비교에서 CMC·BoT-SORT ReID는 껐다.
- 최신 원문과 해시는 B/sources/tracking-v3-7249d7b/에 보존했다. 팀원 원문은 수정하지 않았다.
- 사용자 승인에 따라 윤오름 개인 자료도 갱신했다. 개인 build.py는 B의 공통 장·스타일을 가져오며 통신·GUI 변경·검증 장은 자체 관리한다.

## GUI 논의의 현재 상태

- 사용자는 초기 Qt GUI 구현 기여와 이후 바뀐 GUI 때문에 설명이 혼재된다고 지적했다.
- 이어 실제 데모가 웹 GUI가 아니라고 했고, 현재 B안에서 웹 화면·웹 요청·웹 전송 구조는 제외했다.
- 이후 GUI 논의를 보류했으나, 이번에는 최신 팀원 자료 기준으로 수정하도록 승인했다. 해당 자료의 PC–Runtime TCP 경로와 3종 선택 기능을 발표에 반영했다.
- 현재 24번은 실제 장치 열영상 재생의 상체/전신 표시 사례다. 애플리케이션 GUI 캡처와 다르다. 25·26번은 추적기 선택과 TCP 접수·완료 흐름이다.
- 팀원 자료의 구현 설명을 믿고 사용하되, 실제 데모 앱 캡처·선택값·코덱·제어 설정·교체 후 선택 ID 정책은 최종 확인한다. 이번 편집에서 하드웨어 재시험은 하지 않았다.

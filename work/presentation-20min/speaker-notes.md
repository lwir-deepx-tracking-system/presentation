## 02. 검출 · ID 유지 · 제때 반응, 세 문제를 함께 다뤘다

**시간: 00:20–01:10 / 50초**

이 시스템의 문제는 세 가지입니다. 첫째, 사람을 정확히 찾는 것입니다. 열화상에서는 거리와 가림에 따라 사람의 크기와 형태가 크게 달라집니다. 둘째, 발견한 사람이 앞 프레임의 누구인지 계속 연결하는 것입니다. 번호가 바뀌면 운용자가 선택한 표적과의 연결도 끊길 수 있습니다. 셋째, 그 결과를 늦지 않게 화면과 짐벌에 전달하는 것입니다. 따라서 저희는 검출 정확도, 추적의 연속성, 운용 반응을 나눠 평가했습니다. 팀에서는 모델 학습과 추적 개선, Runtime과 NPU 배포, 제어와 GUI를 나눠 개발하고 통합했습니다.

Python 서버는 NPU에 검출을 요청하고, 결과를 추적과 외형 비교로 연결합니다. 선택한 사람의 위치와 명령은 별도로 실행되는 C++ 짐벌 브리지에 전달됩니다. 브리지 안에서는 기존 Runtime의 제어기와 장치 연결 코드를 재사용해 실제 직렬 명령을 보냅니다. 웹 GUI는 Python 서버에 HTTP로 접속하고, 기존 Qt 앱을 위한 RTP 영상과 UDP 메타데이터, TCP 명령 경로도 별도로 남아 있습니다. 따라서 모든 코드를 Python으로 바꾼 구조는 아닙니다. 기존 제어·통신 기반에 실시간 추적 서버와 웹 운용 기능을 연결한 구조입니다.

## 09. 관측을 다시 활용하는 OC-SORT로 추적 구조를 바꿨다

**시간: 07:50–08:55 / 65초**

검출이 이번 사진에서 사람을 찾는 작업이라면, 추적은 그 사람이 앞 사진의 누구인지 연결하는 작업입니다. ByteTrack은 검출을 높은 점수와 낮은 점수로 나눠 매칭하고 Kalman 예측과 겹침 정도를 사용합니다. 그러나 가려진 동안 예전 속도로 예측이 계속 진행되면 다시 나타난 사람과 연결되지 않을 수 있습니다. OC-SORT는 실제 관측을 더 활용합니다. OCM은 이동 방향을 비교하고, OCR은 마지막으로 본 위치로 다시 매칭하며, ORU는 다시 나타난 관측을 이용해 놓친 구간의 상태를 갱신합니다. 저희는 이 차이를 확인하기 위해 검출 결과를 고정한 채 추적기만 바꿨습니다. 이 비교에서 관측한 개선은 다음 장의 동일 조건 결과로 설명드리겠습니다.

근거: S8 / S9

# 발표 작업 지침

이 폴더에서 발표자료를 수정하거나 새 발표안을 만들기 전에 [HANDOFF.md](HANDOFF.md)로 전체 요구사항·보류 사항을 확인하고 [DESIGN.md](DESIGN.md)를 읽고 따른다. 팀 역할의 상세는 B/team-roles.md를 확인한다.

특히 제목은 `운용 화면`처럼 짧은 명사형으로 쓰고, 작은 분류명과 큰 제목이 겹치는 이중 헤더를 만들지 않는다. 현재 작업본은 C안이며 A·B안은 보존한다. C안의 최신 근거·남은 입력·장 매핑은 C/integration.md를 우선 확인한다.

슬라이드 제목은 LIG 블루(`--blue: #002f6d`)로 통일한다. 첫 장 표지 상단은 로고만 두고, 별도 제목과 구분선을 넣지 않는다. 표지 본문은 공식 프로젝트 제목·팀명·팀원 이름·멘토와 실제 하드웨어 사진으로 구성한다. 슬로건과 시연 화면을 표지에 넣지 않는다. 사진 수령 전에는 자리만 둔다. 예비자료 첫 장에는 일반 제목을 표시한다.

LIG D&A 로고는 제목보다 작게 두고 원본 비율을 유지한다. 오른쪽 끝은 구분선 끝과 맞추되, 제목·로고 아래에 여백을 두어 구분선이 밑줄처럼 붙지 않게 한다. 제목의 실제 글자 영역과 로고의 세로 중심을 맞춘다. 현재 제목 50px, 로고 높이 34px, 제목 아래 패딩 22px·로고 아래 여백 33px이며 본문·예비자료 모두에 적용한다.

하단에는 오른쪽 페이지 표시만 둔다. 초안 상태, 팀명·프로젝트명, 장식 구분선, 출처 링크 행을 표시하지 않는다. 출처와 미확정 사항은 대본·sources.md·인계 문서에 보존한다.

발표 화면에는 작성자 이름·자료 버전·커밋·편집 이력 등 내부 출처 문구를 넣지 않는다. 표지·팀 소개의 이름은 유지한다. 긴 회색 하단 주석과 “○○가 아님” 식의 방어적 설명은 대본·출처 문서로 옮기고, 화면 문구는 구현·비교·측정 결과를 직접 설명한다. 해석에 필요한 데이터셋·실행 환경·계측 구간은 그래프·표 제목에 짧게 표시한다.

실험·추천·자료 갱신 날짜는 본문과 예비 슬라이드에 표시하지 않는다. 날짜 대신 시험 단계·모델·선정 결과로 자연스럽게 설명하고, 정확한 시점은 출처·인계 기록에 보존한다.

발표 시작 순서는 표지 → 목차 → 팀 소개 → 프로젝트 소개이다. 목차는 6개 항목으로 구성하며 마지막 항목과 마무리는 현재 성과 중심으로 정리한다. 별도의 남은 과제 항목을 넣지 않는다. 팀원 역할은 사용자가 제공한 B/team-roles.md를 우선하며, 기존 요약의 역할 추정을 되살리지 않는다.

최종 추적 알고리즘은 사용자 확인에 따라 BoT-SORT로 명시한다. ByteTrack·OC-SORT는 선정 과정의 비교 후보로 설명하고, 본문은 후보 비교 → BoT-SORT 선정 → 최종 설정의 흐름을 따른다. 후보별 지표와 3종 교체 구현 기능은 보존한다. 장치 상태 이력은 예비자료로 관리한다.

팀 소개는 윤오름에 팀장 배지를 붙이고 각자 역할 두 줄로 간결하게 표시한다. 실제 데모는 웹 GUI를 사용하지 않으므로 본문에 웹 UI나 웹 전송 구조를 넣지 않는다. 실제 사용하는 GUI 앱이 확인되기 전에는 특정 앱 화면으로 대신하지 않는다.

최신 팀원 자료 반영: 사용자가 정하건 v3(7249d7b)를 믿고 수정하도록 승인했다. 3종 C++ 추적기와 PC–Runtime TCP 변경·접수/완료·실패 유지 흐름을 발표 근거로 사용한다. 해당 승인으로 윤오름 개인 자료도 갱신했다. 실제 화면·운용 설정과 문서 편집으로 새로 검증하지 않은 범위는 구분한다.

표지에는 팀장 표기 없이 다섯 명 이름만 나란히 둔다. 팀 소개 장의 팀장 배지는 유지한다.

## 01. 표지

안녕하십니까. DEEPX NPU를 이용한 LWIR 표적 추적 시스템 구현을 발표할 5팀 올빼미입니다. 천준호 선임연구원님의 멘토링 아래 다섯 명이 함께 개발했습니다.

화면 단서: 프로젝트 제목 → 5팀 올빼미 → 다섯 명과 멘토

## 02. 목차

먼저 어떤 시스템을 만들었는지 소개하겠습니다. 이어 검출 모델과 추적 알고리즘을 고른 과정, 처리 시간을 줄인 방법을 설명하겠습니다. 마지막으로 주요 성과와 남아 있는 문제를 말씀드리겠습니다.

화면 단서: 프로젝트 소개 → 검출·추적·최적화 → 성과와 한계

## 03. 팀 구성 및 역할

팀장인 저는 시스템 설계와 통신, GUI와 짐벌 제어를 맡았습니다. 김재남 팀원은 Runtime과 멀티스레드 파이프라인, 윤관 팀원은 모델 학습과 경량화, 짐벌 튜닝을 담당했습니다. 정하건 팀원은 추적 알고리즘 검증과 개선, 홍정호 팀원은 Runtime 최적화와 NPU 가속을 맡았습니다.

화면 단서: 이름과 역할 → 구현·최적화 분담 → 시스템 통합

## 04. 프로젝트 소개

저희가 만든 것은 열영상에서 사람을 찾고, 사용자가 고른 사람을 카메라가 따라가도록 하는 시스템입니다. 오른쪽 순서대로 영상을 받아 사람을 검출하고, 사람마다 ID를 붙입니다. 사용자가 ID를 선택하면 짐벌이 그 사람 쪽으로 카메라를 돌립니다. 왼쪽 사진이 장비와 운용 환경입니다.

화면 단서: 왼쪽 장비 → 오른쪽 동작 순서 → 표적 선택과 짐벌 구동

## 05. 시스템 요구사항

입력은 640 곱하기 480 해상도의 열영상이고, 목표는 초당 30장입니다. 한 장의 주기가 약 33.3밀리초라서 처리 목표를 33밀리초로 잡았습니다. 가운데는 이 시간을 단계별로 나눈 설계안입니다. 추적에서는 선택한 ID를 유지하고, 가림 뒤에도 다시 연결하는 기능이 필요합니다.

화면 단서: 30Hz 입력 → 33ms 처리 목표 → 선택 ID 유지와 재포착

## 06. 시스템 구성

카메라 영상은 USB로 Orange Pi에 들어오고, 보드는 NPU에 검출을 요청합니다. 검출 결과를 추적해 선택한 사람의 위치를 구하고, 직렬 통신으로 짐벌을 움직입니다. PC에서는 영상과 상태를 보면서 표적과 운용 모드를 고릅니다. 카메라 방향이 바뀌면 다음 영상에서 다시 표적 위치를 계산합니다.

화면 단서: 카메라→보드·NPU → PC와 정보 교환 → 짐벌과 다음 영상

## 07. 모델 배포 과정

학습과 장치 실행은 이 순서로 연결했습니다. PyTorch 모델을 ONNX로 내보내고, 대표 영상으로 보정해 8비트 정수 모델로 바꿉니다. 마지막으로 M1에서 실행할 DXNN 파일을 만듭니다. 변환 뒤에는 입력 크기와 출력 형식을 맞추고, 좌표와 관절이 제대로 나오는지 점검했습니다.

화면 단서: PyTorch→ONNX → INT8 보정과 DXNN → 출력 점검

넘김: 먼저 검출 모델과 학습 데이터를 어떻게 정했는지 말씀드리겠습니다.

## 08. 검출 모델 선정

왼쪽은 일반 가시광 사진인 COCO의 공개 성능이고, 오른쪽은 도로 열화상 데이터인 FLIR로 직접 학습하고 평가한 결과입니다. FLIR 학습 10,742장과 검증 1,144장을 사용했습니다. 사람 검출 AP는 YOLO26s가 44.93퍼센트로 세 후보 중 가장 높아, YOLO26 계열을 다음 학습의 기준으로 삼았습니다.

화면 단서: COCO 가시광 공개 성능 → FLIR 열화상 직접 비교 → YOLO26 계열 선정

## 09. Full FT와 LoRA

Full FT는 모델 전체를 다시 학습합니다. LoRA는 기존 가중치 대부분을 고정하고 작은 보정 행렬을 학습하는데, 저희 비교에서는 검출 머리도 함께 학습했습니다. 검출 머리는 영상 특징을 받아 사람의 박스 위치와 종류를 예측하는 마지막 부분입니다. 네 데이터 규모에서는 Full FT가 모두 높아, 이번에는 검출 성능을 우선했습니다.

화면 단서: Full FT 전체 학습 → LoRA 보정과 검출 머리 → 이번 조건의 성능 비교

## 10. 현장 데이터 수집 계획

수집 계획은 가림과 잘림, 근거리, 중거리, 원거리 네 조건에 250장씩 배분했습니다. 어려운 장면을 고르게 모으려는 목적입니다. 이후 실제 현장 상체 학습에는 검수한 650장을 사용했습니다. 이 자료에서 특히 신경 쓴 부분이 실내에서 몸이 가려지는 장면입니다.

화면 단서: 네 조건 → 조건별 250장 계획 → 현장 상체 학습

## 11. 실내 근거리 검출의 문제점

실내에서는 노트북이나 손 주변에 사람 박스가 생기거나, 몸이 가려져 박스 크기가 달라지는 문제가 있습니다. 오른쪽처럼 머리나 몸 일부만 잡고 뒤 사람을 놓치는 경우도 있습니다. 박스가 흔들리면 같은 사람을 잇기 어려워지고 짐벌의 조준점도 흔들릴 수 있습니다.

화면 단서: 주변 물체 오탐 → 박스 범위와 누락 → 추적·조준 영향

## 12. 실내 검출을 위한 방법

그래서 박스 기준을 머리 꼭대기부터 골반까지로 맞췄습니다. 하체가 가려져도 같은 상체 범위를 잡으려는 것입니다. 보이는 관절을 공통 골격 틀에 맞춰 범위를 계산하고, 왼쪽 편집 화면에서 상체와 관절을 검수했습니다. 이렇게 정리한 650장과 상체 박스 743개로 추가 학습했습니다.

화면 단서: 가림 전후의 상체 기준 → 실제 라벨 편집 → 650장·743박스

## 13. 데이터 설계 의도

이 자료는 공개 데이터와 자체 촬영 데이터로 나뉩니다. 공개 자료 중 COCO와 MOT17은 가시광 원본을 흑백으로 바꿔 자세와 군중 장면을 보강했습니다. OTP2와 LLVIP는 열화상 자세와 야간 조건을 보강하는 자료입니다. 마지막 자체 자료는 저희 카메라로 촬영하고 직접 검수해 현장 상체 모델을 학습하는 데 사용했습니다.

화면 단서: 공개 가시광 COCO·MOT17 → 공개 열화상 OTP2·LLVIP → 자체 촬영·검수 자료

## 14. 실측 데이터의 증강 방법

왼쪽은 몸 일부를 가린 학습 입력이고, 오른쪽은 인물을 확대해 일부가 화면 밖으로 잘리게 한 입력입니다. 촬영한 장면에 이런 변화를 줘서 몸 전체가 보이지 않는 상황도 학습하도록 했습니다. 가림 합성은 15퍼센트, 부분 확대와 잘림은 50퍼센트의 확률로 적용했습니다.

화면 단서: 촬영 원본 → 가림 합성 → 부분 확대·잘림

## 15. INT8 양자화와 정확도 검증

장치에는 학습이 끝난 모델을 8비트로 바꾸는 PTQ 방식을 사용했습니다. 대표 영상으로 중간 출력 범위를 보정하고 입력 조건을 맞췄습니다. 같은 FLIR 검출기 가중치의 사람 AP는 PC FP32에서 46.62퍼센트, M1 INT8에서 45.95퍼센트였습니다. 양자화와 장치 변환을 거친 정확도 손실은 AP 기준 0.67퍼센트포인트입니다.

화면 단서: PTQ와 대표 입력 보정 → FP32 46.62·INT8 45.95 → 정확도 손실 0.67%p

## 16. 검출 결과

왼쪽 실내 장면에서는 앞사람 검출은 유지됐지만 뒤 사람을 놓친 경우가 남았습니다. 오른쪽 실외 장면에서는 같은 프레임의 중복 박스가 줄었습니다. 아래 공개 검증에서는 상체 박스 AP가 36.04에서 46.28퍼센트로 높아졌고, 재현율은 2.61포인트 낮아졌습니다. 박스 품질은 좋아졌지만 놓침 문제는 남아 있습니다.

화면 단서: 실내 누락 잔존 → 실외 중복 감소 → AP와 재현율

넘김: 다음은 검출한 사람이 이전과 같은 사람인지 이어가는 추적입니다.

## 17. 세 가지 트래커와 GUI 선택

구현한 추적 알고리즘은 ByteTrack, OC-SORT, BoT-SORT 세 가지입니다. ByteTrack을 기준으로 낮은 점수의 검출을 연결하는 방식, 가림 뒤 관측을 복구하는 방식, 박스 크기와 매칭 비용을 보완하는 방식을 비교했습니다. 모두 공통 C++ 인터페이스로 구현했고, GUI에서 선택하면 프레임 경계에서 교체됩니다.

화면 단서: ByteTrack → OC-SORT → BoT-SORT와 GUI 선택

## 18. 세 트래커의 구조

ByteTrack은 점수가 높은 검출부터 연결한 뒤 낮은 점수 후보도 다시 확인합니다. OC-SORT는 실제 관측의 방향과 마지막 위치로 가림 뒤 연결을 보완합니다. BoT-SORT는 폭과 높이를 따로 예측하고 검출 점수를 연결 비용에 반영합니다. 또 카메라 움직임을 보정하는 기능이 있어, 짐벌이 회전하는 상황도 고려할 수 있습니다.

화면 단서: ByteTrack 두 단계 매칭 → OC-SORT 관측 기반 보완 → BoT-SORT와 카메라 움직임

## 19. 세 트래커의 비교

사진으로 보면 왼쪽은 일부가 가려져 검출 점수가 낮아진 상황, 가운데는 벽 뒤로 사라졌다가 다시 나타난 상황입니다. 오른쪽은 카메라가 움직이는 상황입니다. 카메라가 돌면 가만히 있는 사람도 화면에서는 움직이기 때문에, 그 움직임을 추적에 반영하는 기능이 필요합니다.

화면 단서: 저점수 검출 → 가림 뒤 재등장 → 카메라 회전

## 20. 성능 비교

이 표는 카메라 움직임 보정과 외형 비교를 끄고 추적기만 비교한 결과입니다. OC-SORT는 ID 변경이 531회로 가장 적고 재현율도 높았습니다. 반면 BoT-SORT는 검출과 연결을 함께 보는 HOTA가 60.7, 같은 사람의 번호를 얼마나 잘 잇는지 보는 IDF1이 67.5퍼센트로 높았습니다. 저희는 이 종합 품질을 기준으로 BoT-SORT를 선정했습니다.

화면 단서: OC-SORT의 ID 변경·재현율 → BoT-SORT의 HOTA·IDF1 → 최종 선정

## 21. 단순 추적 알고리즘 사용의 한계

왼쪽에서는 두 사람에게 서로 다른 ID가 붙어 있습니다. 가운데에서 박스와 동선이 겹친 뒤, 오른쪽에서는 뒤 사람의 번호가 앞사람에게 넘어갔습니다. 위치와 움직임만으로 구분하기 어려운 장면이라, 사람의 외형을 추가 단서로 사용했습니다.

화면 단서: 교차 전 → 겹침 시작 → 잘못된 ID 연결

## 22. 열영상 외형 특징과 ID 연결

앞 장에서는 두 사람이 겹칠 때 위치만으로 연결하다 번호가 바뀌었습니다. 이를 보완하려고 검출한 사람 조각에서 128차원 외형 특징을 뽑았습니다. 이 특징은 기존 트랙과 새 검출을 매칭하는 단계에서 참고합니다. 위치와 움직임에 외형이 얼마나 닮았는지까지 함께 보고, 이번 프레임에서 어느 ID를 붙일지 결정하는 것입니다.

화면 단서: 검출 뒤 특징 추출 → 기존 트랙과 매칭할 때 비교 → ID 결정

## 23. RepVGG 선택 근거 · 실행 비용

왼쪽은 DX-COM으로 컴파일한 뒤의 연산 그래프입니다. 모델 연산 중 무엇을 NPU에서 실행하고 무엇을 CPU에서 처리하는지 나눠 보여줍니다. CPU로 넘어가는 부분은 전달과 대기도 고려해야 합니다. 이 결과에서 RepVGG는 CPU 노드 없이 NPU로 구성됐고 호출 시간도 짧아, 빠르게 실행할 작은 모델로 골랐습니다.

화면 단서: DX-COM 컴파일 결과 → NPU·CPU 연산 배치 → RepVGG의 실행 비용

## 24. RepVGG 선택 근거 · 검색 정확도

앞 장에서는 작은 RepVGG로 실행 시간을 줄이는 쪽을 봤습니다. 사람을 구분하는 성능을 보완하려고는 큰 SOLIDER를 교사, RepVGG를 학생으로 둔 증류를 검토했습니다. 학생이 교사의 특징과 사람 사이의 구분 관계를 배우게 하는 방식입니다. 학습할 때 큰 모델의 정보를 쓰고 장치에서는 작은 학생만 실행하는 구성으로, 정확도와 지연을 함께 고려했습니다.

화면 단서: 작은 모델의 실행 비용 → 큰 교사의 특징·구분 관계 학습 → 장치에서는 학생만 실행

## 25. KeepID · 가림 뒤 ID 연결 예시

앞의 외형 비교는 이번 검출을 현재 이어지고 있는 트랙 중 누구에게 붙일지 정하는 단계입니다. KeepID는 그 연결이 끊겨 새 트랙이 만들어졌을 때, 최근에 잃어버린 ID를 되찾는 단계입니다. 위치와 크기, 외형을 다시 비교해 원래 번호를 돌려줍니다. 위아래 화면에서 가림 뒤 재등장했을 때 번호가 어떻게 달라지는지 보시면 됩니다.

화면 단서: 기존 트랙 매칭의 외형 비교 → 연결 끊김·새 트랙 → KeepID로 분실 ID 복구

## 26. 외형 특징과 KeepID 적용 결과

열화상 테스트 세 시퀀스에서 세 설정을 비교했습니다. 외형만 켰을 때는 점수가 좋아지지 않았습니다. 외형과 KeepID를 함께 쓴 설정은 외형을 끈 기준보다 HOTA가 2.71포인트, IDF1이 4.51포인트 높았습니다. 다만 MOTA는 낮아져, 번호 연결 개선과 함께 다른 오류도 살펴봐야 했습니다.

화면 단서: 세 설정 → HOTA·IDF1 상승 → MOTA 하락

## 27. 열화상 오차 기반 짐벌 제어와 불감대 튜닝

선택한 상체 박스가 화면 중심에서 얼마나 벗어났는지로 짐벌의 방향과 속도를 정합니다. 작은 오차에는 멈추도록 불감대를 뒀습니다. 실제 짐벌에 가상 표적을 준 시험에서 불감대를 0.04에서 0.06으로 넓히자, 정지 뒤 상하 반전이 네 번에서 한 번으로 줄었습니다. 대신 별도 이동 시험에서는 뒤처짐이 늘었습니다.

화면 단서: 화면 중심과 표적 중심 → 불감대 조정 → 반전 감소와 뒤처짐

## 28. 검출 모델의 정확도와 NPU 지연

지금까지는 더 잘 검출하고 같은 사람을 잇는 정확도를 설명했습니다. 이제는 그 모델을 우리 시스템에서 제때 실행하는 문제입니다. 30Hz 입력에서는 약 33밀리초 안에 처리하는 것이 목표인데, YOLO26s를 m으로 바꾸면 AP는 3.47포인트 높아지는 대신 NPU 시간은 7.53밀리초 늘었습니다. 더 정확하고 무거운 모델을 쓰기 위해, 다음 두 단계로 지연을 줄였습니다.

화면 단서: 정확도 개선에서 실행 시간으로 → 30Hz·33ms 요구사항 → 무거운 모델을 위한 최적화

## 29. 객체 탐지 지연 감소 · 타일 처리

DX-M1의 NPU 코어 중 두 개를 검출에 사용했습니다. 한 코어에 원본 전체를 넣는 대신, 640 곱하기 480 영상 한 장을 좌우 타일로 나눠 코어0과 코어1에 동시에 넣습니다. 가운데 128픽셀을 겹쳐 경계의 사람도 포함했습니다. 두 결과는 원본 좌표로 되돌리고 중복 박스를 합쳐 하나의 검출 결과로 만듭니다.

화면 단서: DX-M1 코어0·1 활용 → 한 프레임을 겹친 좌우 타일로 분할 → 좌표 복원·중복 병합

## 30. 객체 탐지 지연 감소 · 결과

최적화는 두 단계입니다. 첫째, 입력 폭은 640으로 두고 높이를 640에서 480으로 바꿨습니다. 둘째, 그 640 곱하기 480 영상을 384 곱하기 480 타일 두 개로 나눠 두 코어에서 병렬 처리했습니다. 호출 대기 시간 중앙값은 26.687에서 21.621, 최종 18.021밀리초로 줄었습니다. 두 단계를 합쳐 처음보다 약 32.5퍼센트 감소했습니다.

화면 단서: 640×640 → 640×480 → 384×480 두 타일·두 코어

## 31. 실시간 파이프라인과 큐 정책

팀 C++ Runtime에서는 카메라 수신과 검출, 추적, 제어와 화면 송신을 독립 작업으로 나눴습니다. 추론을 기다리는 동안 다른 단계도 진행할 수 있게 한 것입니다. 단계 사이는 큐로 연결하되, 추적에는 순서를 지켜 전달하고 제어와 화면에는 최신 정보를 우선했습니다. 오래된 결과가 계속 쌓이는 것을 줄이려는 구성입니다.

화면 단서: 스레드별 작업 → 큐 연결 → 추적의 순서·제어의 최신성

## 32. PC 애플리케이션과 통신

PC에서는 영상과 박스, ID를 보고 표적과 운용 모드를 선택합니다. 영상과 객체 정보는 따로 전달되므로 RTP 타임스탬프와 프레임 ID로 같은 프레임을 연결합니다. 제어 명령은 TCP로 전달하고, ACK로 명령 처리 결과를, STATUS로 현재 모드와 표적·짐벌 상태를 확인합니다.

화면 단서: 영상·객체 정보 → 프레임 대응 → 명령과 상태 응답

## 33. 주요 성과

검출에서는 상체 기준을 통일해 박스 AP를 높였고, 추적에서는 BoT-SORT의 매칭 조건을 조정해 ID 변경을 줄였습니다. 처리에서는 입력과 타일 구조를 바꿔 지연을 줄이고, 짐벌에서는 불감대를 조정해 반복 반전을 줄였습니다. 열영상에서 사람을 찾는 것부터 표적 선택과 짐벌 구동까지 연결한 것이 전체 성과입니다.

화면 단서: 검출·추적 → 처리·제어 → 시스템 통합

## 34. 검출 문제점과 후속 검증

열화상 카메라는 가시광의 색이나 무늬 대신 적외선 분포로 영상을 만듭니다. 사람과 배경의 열 패턴이 비슷하거나 반사 영향이 있으면 구분할 단서가 줄 수 있습니다. 여기서는 배경에도 사람 박스와 ID가 생겼습니다. 카메라 입력의 이런 제약과 모델의 오탐을 함께 다루기 위해, 반사 조건을 재현하고 오탐 억제 기준을 확인할 계획입니다.

화면 단서: 열화상 입력의 구분 단서 → 배경의 오탐 ID → 반사 조건 재현·억제 기준

## 35. 중·장거리 한계점

멀리 있는 사람은 영상에서 작게 보여 검출이 빠지고, 서로 교차할 때 외형 차이도 줄어 번호를 잇기 어려웠습니다. 거리와 촬영 조건을 나눠 대비 보정 같은 방법을 시험해 볼 계획입니다. 이번에는 현장 데이터와 비교 시험을 바탕으로 검출·추적·제어를 통합했고, 남아 있는 조건도 검증하며 개선해 나가겠습니다. 감사합니다.

화면 단서: 작은 사람의 누락 → 교차 시 ID 유지 → 후속 검증과 마무리

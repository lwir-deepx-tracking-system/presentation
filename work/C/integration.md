## 발표 흐름 개정

- 표지 → 목차 → 팀 소개 → 프로젝트 소개 순서. 목차는 6개 항목이며 15초 배정.
- 마지막 목차 항목은 통합 시연과 주요 성과. 마무리 장은 현재 구현·측정 성과로 구성한다.
- 이전 본문의 거리 검증 계획·현장 ID 검증 계획은 예비자료 36·37장으로 이동. 측정 조건과 실제 입력 관리 항목은 대본·출처·인계에 보존한다.

## 화면 문구

- editorial.py에서 발표용 문구를 관리한다. 작성자·자료 버전·편집 이력과 긴 하단 캡션을 화면에서 제외한다.
- 기존 하단 주석은 condition·editorial_notes와 대본·출처에 보존한다. 핵심 평가 조건은 그래프·표 제목에 표시한다.
- 발표 대본은 구현과 측정 결과를 직접 설명하는 문장으로 정리한다.

## 남은 실제 입력

- 표지 하드웨어 사진 반영 완료: reference/picture/hardware.png → C/assets/hardware.png. 팀원 사진 5개도 같은 공통 폴더에서 동기화한다.
- 실제 GUI 앱 캡처: 기존 재생 이미지는 앱 캡처가 아님.
- C 37장 실제 시연: assets/rooftop-demo.mp4 (180초 이내).
- 최종 검출기·외형 모델 파일 해시, 분할 여부, Runtime/모델뱅크 서버 경로, 추적기, KeepID·가드·lead·보정·제어 인자.
- 거리별 누락·오검출, 가림 뒤 ID 정답·허용 끊김 기준과 현장 반복 결과.
- 사람 있는 최종 장치 경로의 장시간 최대·초과·드롭·순서 오류와 화면·물리 짐벌 종단 측정.

## 자료 충돌 처리

- CMC는 일반 기능 설명과 비교 시 미사용 설정을 분리.
- 최신 개인 요약의 vel/fused 혼용, 512 입력 채택 요약, 추천과 장치 선택을 추가 근거의 조건으로 제한.
- SOLIDER 직접 교체 원본 미확인은 예비자료로 한정.
- 반전 4→1은 Ki0·Kd6 고정의 불감대 비교로 유지.

## 재생성

```powershell
python work/C/build.py
python work/C/render.py
```

render.py는 PDF·미리보기·레이아웃·글꼴·이미지·페이지 수·키보드 이동을 검증한다. validation.json은 실제 하드웨어 검증을 대신하지 않는다.

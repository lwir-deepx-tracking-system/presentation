## 1. DanceTrack 흑백 6 epoch (손실 수정 포함)

- **왜.** 사용자 지시(작업 스크립트의 주석): "train the uploaded FastTrackTr. NPU form, DanceTrack grey 640x480 (36 videos), 6 epochs of a random third of the clip starts each (user: why so slow)". 3~5 epoch의 손실 수정 이유(주석): "ftt_id_check.py showed id_words matched people worse than box position and got worse with training; the official loss rewards collapse" — 사용자 "고쳐". 출처: 개인 실험 기록(run_b4amp*.sh, switch_at_epoch2.sh).
- **데이터.** DanceTrack 학습 36편(흑백 640×480). 한 epoch마다 클립 시작점의 무작위 3분의 1(약 3,164 step).
- **순서.** RT-DETR r18vd COCO 공개 가중치 → epoch 0 → (평가 단계 인자 오류로 멈춰 평가 끄고 이어서) epoch 1~2 → epoch 2 저장 시점에 중단 → 손실 수정판으로 epoch 3~5(로그에는 epoch 6의 1,100 / 3,137 step까지 있고 멈춤).
- **설정.** batch 4, bf16, lr 1e-4(백본 0.1배, 워밍업 1 epoch, 가중치 감쇠 5e-4, 기울기 자르기 0.1), 후보 질의 300, 디코더 2층, 5프레임 묶음. 손실 = DETR(상자 L1·GIoU·분류) + 번호(ID) 손실. 번호 손실: 공식 손실(가중치 1) → 수정판 정규화 circle loss(여백 0.25, γ 64, ×0.05)와 3:4 비율 다중 크기(512×384~768×576).
- **손실 곡선.** epoch 0: 전체 38.2 중 번호 19.3. epoch 1·2(공식 번호 손실): 번호 손실이 평균 0.0004 → 0.0003으로 0이 됨(붕괴), DETR 손실 11.5 → 9.7. 수정 후 epoch 3~5: 번호 18.8 → 14.9 → 13.5, DETR 9.7 → 9.0 → 8.6.
- **결과(DanceTrack 검증 4편, 5프레임 뒤 같은 사람 번호 맞힘).** 공식 손실 epoch 0 54%, epoch 1 46%(학습할수록 나빠짐; 같은 사람 유사도 0.93 대 다른 사람 0.88로 구분 안 됨) → 수정판 **97%**(같은 사람 0.90 대 다른 사람 0.19).
- **왜 채택.** 수정 전 체크포인트는 번호 정보가 사실상 없어 쓸 수 없음.
- **모르는 것.** DanceTrack에서의 추적 점수(HOTA)는 안 쟀음: epoch별 평가가 인자 오류로 꺼졌고 이후 열화상 시험으로 넘어감. 옵티마이저 종류는 설정 파일에 명시 없음. 마지막 epoch 6이 중간에 멈춘 정확한 이유는 기록 없음.

## 2. TMOT 열화상 3 epoch

- **왜.** 학습 계획 7-3절: 공개 시험이 아니라 우리 열화상에서 쓰려고 DanceTrack(가시광 흑백) 판을 열화상으로 이어 학습. 사용자 문장 기록 없음. 출처: model-bank b20d481 tracking_server/research/lwir_pose_plan/README.md 7-3절.
- **데이터.** TMOT 열화상 학습 24편 + DanceTrack 약 30%(샘플 비율 1 : 0.075). 상자는 공개 자료의 몸 전체 상자. 한 epoch 약 2,446 step. 검증용 TMOT 6편은 학습에 안 씀.
- **순서.** 1번의 수정판 마지막 가중치에서 시작, 3 epoch 한 번.
- **설정.** lr 5e-5(백본 0.1배, 워밍업 1 epoch ≈ 2.5천 step: 같은 날 설정 조사에서 RT-DETR이 2천 step 쓴다는 근거), 2 epoch 뒤 0.1배, batch 4, bf16, 옵티마이저 상태는 새로 시작, 5프레임 간격 2(TMOT 5 fps).
- **손실 곡선.** 전체 33.0 → 26.3 → 23.1, DETR 17.2 → 12.9 → 11.3, 번호 15.8 → 13.5 → 11.8. 5프레임 뒤 번호 맞힘 98%(epoch 마지막까지 유지, 다른 사람 유사도 0.13 → 0.05).
- **결과(장치 녹화 재생 IDF1, 6회 판 → 열화상 판).** TMOT 6편 평균 **15.3 → 27.1**, 11개 녹화 중 9개에서 나아짐(헛상자 크게 줄음). 실내 두 녹화는 나빠짐(31.1 → 22.4, 71.2 → 60.0), 사람 5명 녹화는 33.6 → 61.1. 같은 TMOT에서 검출+추적기는 약 66.
- **왜 보류.** 장치에서 한 장 28 ms로 실시간은 가능하지만 기존 방식(검출+추적기)의 절반 이하 점수. 계획 문서: "미리 정한 규칙대로 FastTrackTr 학습은 멈추고(사용자 결정), 학습 서버 시간은 자세 모델에 쓴다. 지금 판은 화면에서 고를 수 있는 시험 기능으로 남긴다."
- **모르는 것.** "미리 정한 규칙"의 원문은 못 찾음. 3 epoch 이상 더 학습하면 따라잡는지는 시험하지 않음. INT8 변환 뒤 정확도 손실은 번호 맞힘 98%에서 변환 전후를 비교한 값이 없음(변환 전후 출력 차이만 6e-6 수준으로 확인).

## 3. 장치 형식

- 3개 그래프(AE, 디코더 층 0, 층 1)로 나눠 INT8 변환, 보정은 우리 야외 녹화 seq_001의 17장(시험 녹화와 겹치지 않음). 한 장 단계 시간 28 ms(AE를 도착 즉시 NPU 2에서 겹침, 겹치지 않으면 약 53 ms). 출처: model-bank b20d481 tracking_server/models/e2e/fasttracktr/INFO.json.

# B안 · 설명 단계를 따라가는 발표

본문 32장 / 예비자료 18장 / 발표 목표 17분 + 데모 3분. 실제 낭독 미측정.

## 디자인 기준

제목·헤더 기준은 ../DESIGN.md를 따른다. 제목은 짧은 명사형 한 줄, 작은 분류명과 큰 제목을 중복 표시하지 않는다. 예: 03번 프로젝트 소개. 향후 개정과 새 안에도 동일하게 적용한다.

## 실제 데모 기준

- 실제 데모는 웹 GUI를 사용하지 않는다. 본문 웹 화면·웹 요청·Python 웹 서버 전송 구조를 제거했다.
- GUI는 실제 데모 앱의 캡처·명령 경로 확인 후 확정한다. Qt 등 특정 앱으로 임의 대체하지 않는다.

## 발표 순서·역할

- 표지 → 팀 소개 → 프로젝트 소개 순서를 유지한다.
- 팀 역할은 team-roles.md의 사용자 제공 내용을 기준으로 한다. 슬라이드 02에는 요약, 문서에는 상세 기여를 보존한다.

## 편집 원칙

- 한 장에서 25–45초 정도 말하고 다음 그림으로 이동한다.
- 문제→방법→결과를 각 장으로 나누고, 도식과 화면의 순서가 말할 순서가 되도록 한다.
- 대본은 참고용. cue-sheet.md의 세 키워드와 화면을 보고 설명한다.
- A안 및 팀 원본을 수정하지 않는다. 출처 스냅샷은 ../A/sources를 공유한다.

## 최종 교체

- 01: 실제 하드웨어 사진. assets/hardware-photo.jpg에 추가하고 build.py·render.py 재실행. 표지에 시연 화면이나 슬로건을 사용하지 않음.

- 04: 거리·ID 유지 기준
- 10–12: 최종 운용 모델과 배포 버전
- 20–23: 실제 제어 설정과 현장 추종 결과
- 24: 실제 데모 앱의 GUI 캡처. 웹 화면을 대체 자료로 사용하지 않음
- 28: assets/rooftop-demo.mp4 (실제 영상 미수령)
- 29–31: 거리·ID 유지·시간의 최종 현장 결과

# 발표자료 디자인·편집 기준

사용자 확정 기준. 이후 수정과 새로운 발표안에도 적용한다.

## 제목과 헤더

- 제목은 짧은 **명사형**으로 쓴다. 예: `운용 화면`, `시스템 구성`, `검출 성능 비교`, `PD 제어`.
- 제목 색은 LIG 블루로 통일한다. 현재 공통 색상 토큰은 `--blue: #002f6d`이며 본문·예비자료 헤더에 동일하게 적용한다.
- 설명문·주장·질문 형태를 큰 제목으로 쓰지 않는다. 예: `한 사람을 고르면, 카메라가 따라간다` 대신 `운용 화면`.
- 상단에는 큰 제목 **한 줄**만 둔다. 작은 분류명·섹션명과 큰 제목을 위아래로 중복 표시하지 않는다.
- 장 번호는 하단 페이지 표시를 사용한다. 섹션과 시간 정보는 대본·큐시트에서 확인한다.
- 제목·로고·구분선의 크기와 위치를 전체 슬라이드에서 통일한다. 헤더가 본문 공간을 과도하게 차지하지 않게 한다.
- 핵심 메시지는 본문의 그림·비교·짧은 문구로 전달한다. 제목에 긴 문장을 몰아넣지 않는다.
- 예비자료도 같은 제목·헤더 기준을 따른다.

## 표지 예외

- 첫 장 표지의 상단에는 LIG D&A 로고만 둔다. 별도 슬라이드 제목과 상단 구분선을 넣지 않는다.
- 표지 본문은 공식 프로젝트 제목·팀명·팀원 이름·멘토와 하드웨어 사진으로 구성한다.
- 표지에는 다섯 명 이름을 한 줄에 나란히 표시하며 `팀장` 직책을 붙이지 않는다. 팀장 배지는 팀 소개 장에서만 표시한다.
- 프로젝트 제목: `DEEPX NPU를 이용한 LWIR 표적 추적 시스템 구현`. 팀명: `5팀 올빼미`. 팀원: 윤오름·김재남·윤관·정하건·홍정호. 멘토: 천준호 선임연구원. 기존 팀 자료의 공식 표기를 따른다.
- `찾고·이어가고·따라가다`나 `쫓아가다` 같은 슬로건을 표지 제목으로 쓰지 않는다.
- 표지 사진은 실제 하드웨어 사진을 사용한다. 시연 화면·녹화 재생 캡처를 대신 넣지 않는다. 사진 수령 전에는 하드웨어 사진 자리만 표시한다.
- 현재 공통 사진은 `reference/picture/hardware.png`, 팀원 사진은 같은 폴더의 이름별 PNG다. C안은 공통 사진을 `C/assets/`로 복사해 사용하며 C 빌더 재실행 시 동기화한다. B안의 이전 사진 경로 `B/assets/hardware-photo.jpg`는 보존한다.
- 이 예외는 본문 첫 장 표지에만 적용한다. 예비자료 첫 장은 일반 헤더 기준을 따른다.

## LIG D&A 로고 정렬

- 로고는 제목보다 작게 두어 제목과 시각적 균형을 맞춘다. 현재 기준은 제목 50px, 로고 이미지 높이 34px이다. 같은 픽셀 높이로 맞추면 로고가 과도하게 커지므로 사용하지 않는다.
- 원본 로고의 가로세로 비율을 유지한다. 늘리거나 눌러서 크기를 맞추지 않는다.
- 로고 오른쪽 끝은 상단 구분선의 오른쪽 끝과 맞춘다.
- 제목·로고와 구분선 사이에 충분한 여백을 둔다. 현재 제목 아래 패딩 22px, 로고 아래 여백 33px이다. 구분선에 글자나 로고의 아래쪽을 붙여 밑줄처럼 보이게 하지 않는다.
- 제목과 로고는 같은 헤더 행에서 시각적으로 균형 있게 배치하고, 로고 영역을 침범하지 않도록 제목 오른쪽 공간을 확보한다. 오른쪽 끝 정렬과 아래쪽 여백은 별개의 기준이다.
- 제목의 실제 글자 영역과 로고의 세로 중심 높이를 맞춘다. CSS 박스의 아래쪽을 같게 놓는 것만으로 정렬을 판단하지 않는다. 현재 로고는 이전 위치보다 9px 올렸으며, 크기는 그대로 유지한다.
- 본문과 예비자료 모두 같은 크기·정렬을 사용한다. PDF와 미리보기에서도 실제 정렬을 확인한다.

## 하단 페이지 표시

- 하단에는 오른쪽의 `02 / 32` 같은 페이지 표시만 둔다.
- `확정 전 초안`, `5팀 올빼미 · LWIR 표적 추적` 등 상태·팀명·프로젝트 문구를 넣지 않는다.
- 하단 장식 구분선과 슬라이드별 출처 링크 행도 표시하지 않는다. 출처는 대본과 sources.md에 보존한다.
- 긴 회색 하단 캡션과 작성자·자료 버전·커밋 등 내부 출처 표기는 화면에서 제외한다. 출처와 세부 조건은 대본·sources.md·인계 문서에 보존한다. 데이터셋·실행 환경·계측 구간 등 핵심 조건은 그래프·표 제목에 짧게 넣는다.
- “○○가 아님”, “○○로 해석하지 않음” 같은 편집자 관점의 문장 대신 구현 내용과 관측 결과를 직접 설명한다. 표지·팀 소개의 이름과 실제 측정값·절충은 유지한다.
- 본문과 예비자료 모두 같은 기준을 적용하고, 재생성 후에도 유지한다.

## 설명 흐름

- 팀 소개 다음에는 프로젝트를 모르는 청중을 위한 개요를 둔다. 무엇을 만드는지, LWIR·NPU가 무엇인지, 입력→인식→표적 선택→추종 흐름을 먼저 설명한다. 운용 화면이나 조작법으로 시작하지 않는다.
- 발표 시작 순서는 **표지 → 목차 → 팀 소개 → 프로젝트 소개**로 한다. 목차는 6개 항목을 2열×3행으로 배치하고, 마지막 항목은 `통합 시연과 주요 성과`로 쓴다. 마무리는 현재 성과 중심으로 구성하며 별도의 남은 과제 항목은 두지 않는다.
- 팀 소개는 사용자가 제공한 [팀원 담당 업무](B/team-roles.md)를 기준으로 한다. 사진별 주요 담당과 핵심 기여를 같은 형식으로 요약하고, 상세 업무는 문서와 대본에 보존한다.
- 팀 소개에서 윤오름은 `팀장` 배지로 표시한다. 각자 핵심 역할은 두 줄만 남기고 중복되는 역할 제목·세부 업무 나열은 덜어낸다.
- 실제 데모는 웹 GUI를 사용하지 않는다. 웹 GUI 화면·조작·전송 구조를 본문 운용 설명이나 데모 근거로 넣지 않는다. 실제 사용하는 앱이 확인되기 전에는 다른 앱 화면을 대체하지 않는다.
- 20분이라고 슬라이드 수를 적게 제한하지 않는다. 현재 B안은 본문 32장이다.
- 발표자가 긴 대본을 암기하지 않고 화면 순서대로 설명할 수 있게 문제·방법·결과를 나눈다.
- 그림과 도표에 설명할 순서와 핵심 단서를 둔다. 한 장에 긴 설명을 모두 넣지 않는다.
- 세부 조건은 대본·출처·예비자료에 보존하고, 실제 녹화·합성 미리보기·개념도는 구분해서 표시한다.

## 결과 비교 그래프

- 본문 설명의 기본 단위는 **문제 → 변경 방법 → 측정 결과 → 채택·절충**이다. 모든 장을 수치 변화 카드로 만들거나 서로 다른 실험을 한 개선 곡선에 연결하지 않는다.
- 그래프는 단계별 설명의 근거로 쓰고, 마지막에 단계별 결과와 적용 범위를 한눈에 정리한다. ‘그래프 모음’과 ‘숫자 화살표 반복’ 중 하나만 택할 필요는 없다.
- 새 핵심 결과는 본문 안에서 이해되게 구성한다. 사용자 의향에 따라 예비자료를 열어야 발표가 완성되는 구성에 의존하지 않는다. 기존 상세 예비자료는 보관용이다.
- 요약 카드만으로 화면이 비지 않도록 실제 라벨링·증강·관측 영상과 구조도·실측 그래프를 설명 단계에 맞춰 활용한다. 원본 전체 슬라이드를 작은 이미지로 붙이기보다 필요한 그림을 가져와 통합본의 글자 크기와 여백으로 재구성한다. 실측 곡선과 개념·응답 모형을 표시로 구별하고 출처·조건은 문서에 보존한다.
- 결과가 좋지 않아 교체를 보류한 대조 실험도 선택 근거가 분명하면 본문에 넣는다.
- 비교 결과는 큰 숫자와 화살표만 나열하지 않고, 차이를 볼 수 있는 그래프로 표시한다.
- 두 조건 비교는 같은 축의 막대그래프와 실제 값, 별도의 변화량 표시를 함께 사용한다.
- 막대는 0부터 시작하는 선형 축을 쓴다. 작은 차이를 크게 보이게 축을 자르지 않는다.
- 단위·높고 낮음의 의미·비교 조건을 명시한다. AP나 IDF1의 차이는 %p, 상대 감소율은 %로 구분한다.
- 좋아진 결과뿐 아니라 시간 증가나 제어 뒤처짐 악화도 표시한다. 다른 단위와 다른 시험은 그래프를 분리한다.
- 학습 경과처럼 실제 연속 기록이 있으면 곡선을 쓰고, 전후 두 값만으로 가상의 변화 경로를 만들지 않는다.

## 작업 및 인계

- C안 대본은 `C/spoken_script.py`에서 최종 적용한다. 짧은 말할 내용·화면 진행·선택 전환을 구분하며, 근거·조건은 대본의 별도 영역에 보존한다. 생성된 notes 파일만 수정하지 않는다. 거리 기준은 `XX~XX m` 자리로 유지하고 실측 전 수치를 임의로 채우지 않는다.
- 현재 작업본은 `B/`. A안과 팀원 원본은 별도 요청 없이 수정하지 않는다.
- 생성 결과만 수정하지 말고 `B/build.py`, `B/slides.css`에도 반영한다.
- 변경 후 HTML·PDF·미리보기·대본·큐시트를 다시 생성하고 제목·헤더와 잘림을 확인한다.
- 새 발표안을 만들 때도 이 문서의 제목·헤더와 설명 흐름 기준을 이어받는다.

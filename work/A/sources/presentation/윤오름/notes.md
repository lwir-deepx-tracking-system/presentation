# LWIR 프로젝트 발표 노트

조사일: 2026-11-16. 모델뱅크 웹 GUI 기준 수정 반영. GitHub 공개 변경 기록·기본 브랜치 파일과 Notion 작업 기록을 대조한 내용 초안이다. 발표 담당 확정표가 아니며 실제 개발·설계·통합 기여에서 발표 범위를 도출했다. 이번 조사에서 빌드·보드 시험은 수행하지 않았다.

## 담당 범위 판단

- 중심: 10 표적 선택과 짐벌 제어, 12 PC 애플리케이션과 통신.
- 함께 초안 작성: 4 요구사항과 설계 기준, 5 전체 시스템 구성, 13 시험 및 성능 결과.
- 공동 설명 범위: 11 실시간 처리와 영상 송신. PC 연동·송수신 정합·계측은 다룰 수 있으나 Runtime 파이프라인 전체나 인코더 구현을 단독 기여로 표현하지 않는다. 영상 변경 PR #7 작성자는 seu20이고, 이후 통신 정합 PR #9와 통합 PR #10 작성자는 x-orme다. 통합 PR 작성자와 포함된 모든 코드의 원저자는 같다고 볼 수 없다.
- 기존 1·3번은 디자인 예시다. 예시 제작을 발표 담당 배정으로 해석하지 않는다.
- 6·7·8·9번의 모델·양자화·전후처리·추적 알고리즘 상세는 해당 개발자의 근거를 반영한다.

## 01. 표지 — 20초

기존 index.html의 표지를 통합했다. 프로젝트명·팀원·멘토와 운용 개념도를 유지한다.

발표 노트: “안녕하십니까. DEEPX NPU를 이용한 LWIR 표적 추적 시스템 구현을 발표할 5팀 올빼미입니다. 열영상으로 객체를 검출하고, 선택한 표적을 추적해 2축 짐벌 제어로 연결한 시스템을 소개하겠습니다.”

화면 구성: 누끼 인물 사진 5장을 가로로 배치하고, 이름·주요 역할·세부 담당 업무를 표시한다. 팀장과 멘토를 함께 소개한다.

## 03. 프로젝트 목표와 운용 시나리오 — 1분

기존 index.html의 운용 시나리오를 통합했다. 열화상 객체 검출 → 표적 선택 → 추적·짐벌 제어와 영상 피드백 흐름을 유지한다.

발표 노트: “운용은 세 단계입니다. 열영상에서 객체를 검출하고, 사용자가 PC에서 추적할 표적을 선택합니다. 시스템은 선택 객체의 ID를 따라가며 설정한 조준점과 영상 중심의 오차로 짐벌을 제어합니다. 짐벌 회전으로 바뀐 영상을 다시 받아 같은 과정을 반복합니다.”

도식은 운용 개념이며 실제 장치 사진이나 측정 결과가 아니다.


## 04. 시스템 요구사항 — 1분 20초

핵심 문장: **열영상 입력부터 표적 추종·상태 확인까지, 시스템이 충족해야 할 기준을 정의한다.**

| 구분 | 요구사항 | 목표·확인 기준 |
| --- | --- | --- |
| R1 실시간 처리 | 30Hz 입력 영상의 한 프레임 처리를 약 33.3ms 이내에 완료해야 한다. | 프레임 처리시간 ≤ 33.3ms |
| R2 객체 검출 | 지정된 거리 범위 안에서 대상 객체를 검출할 수 있어야 한다. | 최소·최대 검출 거리 [기준 확정 필요] m |
| R3 객체 추적 | 동일 객체의 ID를 유지하며 정해진 기준 이상으로 추적을 유지해야 한다. | 최소 유지 시간·유지율 [기준 확정 필요] |
| R4 짐벌 추종 | 사용자가 추적 명령을 내린 객체를 2축 짐벌 제어로 추종해야 한다. | 선택 표적의 Pan·Tilt 추종 |
| R5 PC 운용 | PC GUI에서 영상·추적 결과·현재 시스템 상태를 확인할 수 있어야 한다. | 영상·표적·운용 상태 표시 |

화면 구성: 구분·요구사항·목표 기준을 담은 5행 표. 구현 방법은 이후 기술 슬라이드에서 설명한다.

발표 노트: “시스템 요구사항은 다섯 가지입니다. 첫째, 30Hz 입력에 맞춰 한 프레임 처리를 약 33.3ms 이내에 완료하는 것을 목표로 합니다. 둘째, 지정 거리 범위에서 객체를 검출해야 합니다. 셋째, 같은 객체의 ID를 유지하며 정해진 기준 이상으로 추적해야 합니다. 넷째, 사용자가 선택한 표적을 2축 짐벌로 추종해야 합니다. 마지막으로, PC GUI에서 영상과 추적 결과, 운용 상태를 확인할 수 있어야 합니다.”

기준: 2026-11-16 사용자 설명. 수치는 달성 결과가 아닌 목표다. 검출 거리, 추적 시간·유지율은 임의로 확정하지 않았다. 검출 시험의 객체 종류·판정 지표·환경 조건과 추적 유지율의 분모·ID 변경 처리·가림 조건을 확정해야 한다. 33.3ms의 처리 시작·종료 지점과 평균·최대 등 판정 통계도 시험 전에 확정한다. 병렬 파이프라인의 처리량과 개별 프레임 지연은 구분하여 검증한다.

## 05. 전체 시스템 구성 — 1분 20초

핵심 문장: **보드가 검출·추적·구동을 수행하고, 웹 GUI가 표적 선택과 운용 상태 확인을 담당한다.**

화면: 카메라 → Orange Pi/DEEPX NPU의 검출·추적 → C++ 제어 브리지 → USB Serial 짐벌. PC·휴대폰 브라우저는 보드의 HTTP 8090 서버에서 영상·상태를 받고 선택·이동·정지를 요청한다.

발표 노트: “시스템은 열화상 카메라, Orange Pi와 DEEPX NPU, 2축 짐벌, 그리고 웹 GUI로 구성됩니다. 보드는 객체 검출과 추적을 수행하고, C++ 브리지를 통해 짐벌을 구동합니다. 사용자는 PC나 휴대폰의 브라우저에서 영상을 보고 표적을 선택하며 현재 상태를 확인합니다. 기존 제어기와 장치 실행 경계를 재사용하고, Python 실시간 서버와 웹 화면을 연결했습니다.”

웹 영상은 /stream의 JPEG multipart, 명령은 HTTP POST, 상태는 JSON 조회다. 기존 Qt PC 앱의 RTP/UDP 5000·메타데이터 UDP 5001·TCP 5002 경로도 브리지에서 별도로 지원한다. 두 인터페이스를 혼합해 웹 브라우저가 기존 RTP 수신 클래스를 사용한다고 설명하지 않는다.

근거: [서버·HTTP 처리](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/web/page_handler.py), [기존 코드 출처](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/gimbal/team/SOURCE.txt), [브리지](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/gimbal/gimbal_bridge_v25.cpp).

## 10. 표적 선택과 짐벌 제어 — 1분 10초

핵심 문장: **선택 표적의 조준점 오차를 PD 제어로 보정하고, 수동 개입과 입력 상실에는 정지한다.**

화면: BBox 조준점과 영상 중심 사이 오차 도식 → PD·출력 제한 → 단일 장치 실행 경로. 조준점은 cx=x+w/2, cy=y+αh다. 원본 640×480에서 중심은 (320,240)이다.

발표 노트: “사용자가 영상에서 객체를 클릭하면 해당 ID의 최신 관측을 바탕으로 조준점과 화면 중심의 오차를 계산합니다. 공개 실행 스크립트는 Kp 30, Ki 0, Kd 6의 PD 동작을 사용합니다. BBox 중심 대신 설정한 높이를 조준점으로 쓰며, 공개 기본값은 위에서 8% 지점입니다. 방향과 공통 속도를 결정하고 Deadband, 속도 상한과 변화율 제한을 적용합니다. 웹 명령과 자동 추종을 기존 제어 실행 경계에 연결하고, Space 정지와 수동 입력 해제, 표적·입력 상실을 처리합니다.”

공개 설정과 실제 보드 설정은 구분한다. scripts/live.env와 추가 옵션이 값을 덮어쓸 수 있으며 이번 작업에서는 조회하지 않았다. 기본 v25 기준으로 설명하고, v27의 coast·guard·탐색 등은 실제 켠 기능을 확인한 뒤 반영한다. 두 축 방향은 따로 계산하지만 SPD는 장치 공통 속도이며 실제 °/s가 아니다. Space는 웹에서 STOP이고 원점 복귀가 아니다.

근거: [공개 실행 스크립트](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/scripts/run_real_gui.sh), [웹 조작](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/page/js/03_gimbal_control.js), [제어 변경 기록](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/gimbal/V27_CHANGES.md).

## 11. 실시간 처리와 웹 영상 송신 — 1분 50초 / 공동 설명

핵심 문장: **검출·추적 결과를 제어와 화면으로 나누고, 웹 영상의 최신성을 관리한다.**

화면: Camera → Detection → Tracking → 웹 영상 / C++ 제어 브리지 분기. 하단은 기본 영상·박스 결합 경로와 선택 기능 Picture First 비교다.

발표 노트: “검출·추적 결과는 제어와 화면 경로로 나뉩니다. 기본 웹 경로는 서버가 결과 박스를 영상에 그린 뒤 JPEG로 전송합니다. 선택 기능인 Picture First를 켜면 카메라 영상을 먼저 보내고 검출·추적 박스를 별도 이벤트로 전달해 브라우저가 겹쳐 그립니다. 이 경우 영상은 최신 상태를 먼저 보여주지만 박스가 늦게 도착하는 절충이 있습니다. 기존 Qt 앱의 RTP 영상과 메타데이터 경로는 별도로 지원하므로 구분해서 설명합니다.”

Picture First는 환경변수 또는 웹 설정으로 켜는 옵션이다. 실제 활성 여부는 미확인이다. 같은 프레임 영상·박스의 엄격한 대응과 영상 최신성 우선 정책을 동일한 보장으로 표현하지 않는다. 서버 처리·JPEG 준비·브라우저 표시 구간은 나누어 해석한다. 기존 하드웨어 JPEG/H.264 비교표는 웹 경로의 주 설명에서 제외했다. NPU·worker 세부 설계는 김재남 자료와 대조해 취합한다.

근거: [화면 발행](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/web/page_handler.py), [Picture First](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/web/picture_first.py), [스트림 송신](https://github.com/lwir-deepx-tracking-system/model-bank/blob/5ea5b64bcf2be43cc74e30e7ea8492b22d081a11/tracking_server/src/web/stream_sender.py).

## 12. 웹 GUI와 운용 인터페이스 — 1분

핵심 문장: **브라우저에서 표적 선택·짐벌 조작·설정·상태 확인을 통합했다.**

화면: model-bank의 images/interface_8090.png 미리보기와 핵심 기능 네 개. 해당 이미지는 합성 영상·예시 수치의 PC 미리보기이며 실제 장치 연결 캡처가 아니다. 로컬 파일은 assets/model-bank-web-gui.png다.

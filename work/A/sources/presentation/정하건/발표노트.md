# 추적 알고리즘 발표 노트 (정하건)

슬라이드 4장, 약 3분 기준. 쪽 번호는 최종 취합 때 바뀔 수 있습니다.

## 01 추적 알고리즘: ByteTrack에서 OC-SORT로 (40초)
- 추적은 프레임마다 같은 사람에게 같은 번호(Track ID)를 붙이는 일입니다. 운용자가 고르는 것이 이 ID라서, ID가 바뀌면 짐벌이 표적을 잃습니다.
- ByteTrack을 C++로 구현해 옵션 14가지를 비교했고, OC-SORT를 같은 검출로 정면 비교한 뒤 채택해 LWIR에 맞게 조정했습니다.
- 결과적으로 ID 전환은 2,964회에서 531회로, IDF1은 49.6%에서 66.7%로 좋아졌고, 18개 시퀀스 모두에서 OC-SORT가 앞섰습니다.

## 02 두 알고리즘의 구조 차이 (40초)
- ByteTrack은 검출을 점수로 나눠 두 번 매칭하고, Kalman 필터가 다듬은 박스를 출력합니다. 움직임 판단은 Kalman 예측에만 기댑니다.
- OC-SORT는 실제 관측을 중심에 둡니다. 이동 방향(OCM)을 매칭에 더하고, 놓친 Track은 마지막 관측 위치로 다시 찾으며(OCR), 다시 찾으면 놓친 구간의 상태를 다시 계산합니다(ORU). 출력은 검출 박스 그대로입니다.
- OC-SORT는 공식 Python 구현과 출력이 같은 것을 확인했습니다.

## 03 성능 비교와 개선 원인 (60초)
- 같은 검출로 비교하면 OC-SORT가 IDF1 64.1%, ID 전환 775회로 ByteTrack 최선(49.6%, 2,964회)을 앞서고, 헛출력도 3분의 2 수준입니다.
- 원인은 장면마다 다릅니다. 정지 장면은 검출 박스를 그대로 내서 작은 박스의 위치 오차가 줄었고, 교차는 이동 방향으로 엇갈린 두 사람을 구분했습니다.
- 방향을 바꾸거나 가려졌다 나타나는 경우, ByteTrack은 놓친 동안 예측이 엉뚱한 곳으로 밀려 새 ID를 만들었는데, OC-SORT는 놓친 구간을 다시 계산하고 마지막으로 본 위치로 다시 이어 줍니다.

## 04 최종 파라미터와 옵션 (40초)
- LWIR 검출 점수가 낮아 검출 기준은 0.5로, 바로 출력하고 낮은 점수 검출도 2차 매칭에 씁니다.
- 작은 박스가 잘 이어지도록 같은 사람으로 인정하는 겹침 기준을 0.3에서 0.2로 낮췄습니다. 0.15는 옆 사람에게 잘못 이어 붙었습니다.
- ByteTrack에서 효과를 본 두 기능을 옵션으로 추가했습니다. 박스를 넓혀 다시 매칭해 ID 전환을 줄이고, 놓친 1프레임은 예측 박스로 이어 박스 끊김을 줄였습니다. 정밀도 1.1%p를 내주는 대신 표적을 잃는 횟수를 줄이는 쪽을 택했습니다.

# 추적 알고리즘 발표 노트 (정하건)

슬라이드 9장, 약 6분 기준. 쪽 번호는 최종 취합 때 바뀔 수 있습니다.

## 01 추적 알고리즘: ByteTrack에서 OC-SORT로 (30초)
- 검출이 사람을 찾는다면, 추적은 프레임마다 같은 사람에게 같은 번호(Track ID)를 붙이는 일입니다.
- 운용자가 화면에서 고르는 것이 이 ID라서, ID가 바뀌면 짐벌은 그 순간 표적을 잃습니다.
- ByteTrack을 먼저 구현·개선했고, OC-SORT를 같은 조건으로 비교해 최종 채택했습니다. 결과적으로 ID 전환이 2,964회에서 531회로 줄었습니다.

## 02 평가 지표와 추적 옵션 (40초)
- 이후 쪽에서 쓰는 말을 먼저 정리합니다. 운용에서 가장 중요한 것은 IDSW(ID가 바뀐 횟수)와 IDF1(같은 사람을 같은 ID로 이은 비율)이고, HOTA는 검출과 연결을 함께 본 종합 점수입니다.
- 옵션은 ByteTrack 개선용(NSA, XYWH), OC-SORT 고유 단계(OCM 이동 방향, OCR 마지막 관측 재매칭, ORU 재등장 시 상태 재계산), 그리고 두 추적기에 모두 넣은 추가 옵션(Buffered IoU, L1)으로 나뉩니다.
- OC-SORT 고유 단계도 ByteTrack에 옵션으로 이식해 비교했고, 모든 옵션은 끄면 원래 알고리즘과 출력이 같도록 만들었습니다.

## 03 두 알고리즘의 구조 차이 (50초)
- ByteTrack은 검출을 점수로 나눠 두 번 매칭하고, 출력은 Kalman 필터가 다듬은 박스입니다. 움직임 판단은 Kalman 예측에만 기댑니다.
- OC-SORT는 실제 관측(검출)을 중심에 둡니다. 이동 방향 일치도(OCM)를 매칭에 더하고, 놓친 Track은 마지막 관측 위치로 다시 찾으며(OCR), 다시 찾으면 놓친 구간의 상태를 다시 계산합니다(ORU). 출력은 검출 박스 그대로입니다.
- 두 추적기 모두 C++로 직접 구현했고, OC-SORT는 공식 Python 구현과 무작위 장면 60개에서 출력이 같은 것을 확인했습니다. 설정 파일의 tracking.id로 전환합니다.

## 04 ByteTrack 개선 실험 (40초)
- Kalman 형식(XYWH), NSA Kalman, 버퍼·놓친 프레임 출력, Buffered IoU, OCR 등 14개 조합을 Orange Pi에서 18개 시퀀스로 비교했습니다.
- 가장 효과가 큰 것은 Buffered IoU로, 박스를 넓혀 다시 매칭해 작은 박스의 매칭 실패를 구제했습니다(IDF1 +6.2%p).
- 검출 점수를 매칭 비용에 곱하는 fuse_score는 LWIR 검출 점수가 낮아 매칭이 무너졌습니다.
- 최선 조합(Buffered IoU + OCR)도 ID 전환이 약 3천 회 남아 구조 자체를 바꾼 OC-SORT를 비교했습니다.

## 05 ByteTrack 최선 vs OC-SORT (50초)
- 같은 YOLO26s 검출로 돌렸습니다.
- OC-SORT 공식 기본값은 ID 전환이 425회로 가장 적지만, 누락이 47,178개로 쉬운 사람만 따라간 결과였습니다(검출 점수 기준 0.6, 3프레임 확인 뒤 출력).
- LWIR 점수에 맞춰 기준 0.5, 바로 출력, 낮은 점수 2차 매칭으로 조정하자 누락은 ByteTrack 수준이면서 IDF1 64.1%, IDSW 775로 앞섰습니다.
- 18개 시퀀스 각각에서도 IDF1, HOTA, IDSW, 헛출력 모두 OC-SORT가 우세했습니다.

## 06 성능 향상의 원인 (60초)
- 장면 유형별로 ByteTrack이 ID를 잃은 원인과, 그 원인에 대응하는 OC-SORT 단계를 짝지었습니다. 수치는 실측, 원인과 대응은 분석입니다.
- 정지: ByteTrack은 Kalman이 다듬은 박스를 내는데, 작은 박스에서는 실제 위치보다 조금만 늦거나 커져도 정답과 IoU가 떨어져 헛출력과 누락이 함께 생깁니다. OC-SORT는 검출 박스를 그대로 내서 DetA가 18개 시퀀스 모두에서 올랐습니다.
- 교차: 두 사람이 겹쳤다 갈라지는 순간 IoU만으로는 누가 누구인지 구분할 정보가 없습니다. OC-SORT는 이동 방향(OCM)을 비교해 방향이 맞는 쪽과 짝을 짓습니다. IDSW 1,064 → 300.
- 불규칙 이동: 놓친 동안 Kalman은 예전 속도로 예측을 계속 밀어내, 방향을 바꾼 사람이 다시 보이면 예측과 겹치지 않아 새 ID가 생깁니다. ORU가 놓친 구간을 보간해 속도를 다시 계산합니다. IDSW 418 → 72.
- 접근·가림: 가려진 동안 예측 위치가 표류합니다. OCR이 표류한 예측 대신 마지막으로 본 위치로 다시 매칭합니다. IDSW 1,009 → 271.
- 참고: MOT17(보행자 공개 데이터)에서는 조정한 OC-SORT의 ID 전환이 ByteTrack보다 많았습니다. 박스가 큰 데이터에서는 이런 이점이 작아, LWIR 실데이터로 결정했습니다.

## 07 OC-SORT 파라미터 조정 (40초)
- 검출은 고정한 채 추적기만 PC에서 다시 돌려 파라미터를 하나씩 바꿨습니다. 기준값은 Orange Pi 결과와 IDSW 784 대 775로 일치했습니다.
- 매칭 기준 IoU를 0.3 → 0.2로 낮추자 HOTA가 가장 높았습니다. 0.15에서는 ID 전환은 더 줄지만 옆 사람에게 잘못 이어 붙어 HOTA·IDF1이 떨어졌습니다.
- 검출 기준을 낮추면 ID 전환이 늘었고, max_age(60, 50), delta_t, inertia는 차이가 거의 없어 기본값을 유지했습니다.

## 08 추가 옵션: Buffered IoU와 L1 (40초)
- ByteTrack에서 효과를 본 두 기능을 OC-SORT에 옵션으로 넣었습니다. 끄면 공식 구현과 출력이 같도록 만들어 검증을 유지했습니다.
- Buffered IoU는 ID 전환을 줄였고, L1(놓친 1프레임은 예측 박스로 계속 출력)은 박스 끊김을 줄였습니다.
- 둘을 함께 쓰면 정밀도는 1.1%p 낮아지지만 ID 전환 −19%, 끊김 −15%입니다. 짐벌 운용에서는 표적을 잃는 쪽이 더 치명적이라 함께 채택했습니다.

## 09 최종 선택: 조정한 OC-SORT (40초)
- 최종 설정은 검출 기준 0.5, 바로 출력, 낮은 점수 2차 매칭, 매칭 IoU 0.2, Buffered IoU 0.5, 놓친 프레임 출력 1입니다.
- ID 전환은 ByteTrack 최선 2,964회에서 OC-SORT 조정 775회, 최종 531회로 줄었습니다. 마지막 단계는 같은 검출을 PC에서 다시 돌린 결과입니다.

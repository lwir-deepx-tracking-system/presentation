# 학습 기록 · 위치 기억(GRU·Mamba)

사람이 가려져 검출이 끊긴 동안 상자가 어디 있을지 예측하는 작은 모델의 기록입니다. 결정에 쓴 비교만 남겼고 전체 표는 작성자 PC의 개인 기록에 있습니다. 출처는 `model-bank <커밋> <파일>`과 `개인 실험 기록(<파일 이름>)`입니다. 기록이 없는 것은 "기록 없음"입니다. 오차는 모두 "놓친 뒤 5·10·15장 평균 중심 오차 / 사람 키"(낮을수록 좋음)입니다. 손실 곡선: [위치예측_학습곡선.csv](학습로그/위치예측_학습곡선.csv). 그림은 부록 장 `위치 예측 학습`, `위치 예측 손실 곡선`에 있습니다.

## 1. 11-15 TMOT·DanceTrack 재학습 (GRU·Mamba)

- **왜.** 사용자 문장 기록 없음. 11-15 사용자 "2번부터 하자"(상자 다듬기와 위치 기억을 같은 자료로 함께). 기존 PoseTrack18 판은 우리 검출기 입력에서 Kalman과 비슷하거나 조금 나빴음. 출처: 개인 실험 기록(PREREG_POS_REFINE_20261115.json, SUMMARY_KO.md).
- **데이터.** 우리 근거리·원거리 자세 검출기를 장치와 같은 방식(같은 출력 갈래, 서버 NMS, 점수 0.10 초과)으로 TMOT 열화상 학습 24편(+평가 6편)과 DanceTrack 40편(640×480 흑백)에 돌린 **검출 출력**. 약 5만 장 × 2 검출기. 분할은 사전 등록: val-A(모든 선택용) = TMOT 5편 + DanceTrack 4편, val-B(보고용) = TMOT 평가 6편 + DanceTrack 8편, 나머지 학습. 검출과 정답이 이어진 비율 TMOT 근거리 49~53%, 원거리 71~74%, DanceTrack 73~83%.
- **순서.** (a) 처음부터 lr 2e-3 (b) 옛 PoseTrack18 파일에서 시작 lr 5e-4, 각각 GRU·Mamba → 선택 점수(val-A, (전체 + 합성 사라짐) / 2)로 설정과 epoch 선택.
- **설정.** 입력 프레임당 68개(상자 값 + 화면 가장자리까지 거리 + 관절 17개의 위치·보임), 놓치기 전 최대 20프레임. GRUCell 68→64(머리 4개: 중심 ±1 키, 크기 ±50%) 또는 Mamba d 48, 출력 15프레임. 손실 = 중심 오차/키의 smooth L1 + 로그 크기 + (1 − GIoU). AdamW(wd 1e-4), cosine 최소 2%, batch 512, 최대 30 epoch. 증강: 시간 뒤집기·좌우 반전·반 프레임율·합성 사라짐(가리개가 지나가게 함). 자료 변형 4회.
- **손실 곡선.** 학습 손실 GRU 0.815(1 epoch) → 0.709(30), 검증 점수 0.279 → 0.238. 선택: (a)가 이김(GRU 0.2417 대 0.2589, Mamba 0.2432 대 0.2657) → (a)의 26 epoch.
- **결과(val-B, TMOT / DanceTrack).** Kalman 0.352 / 0.295, 옛 GRU 0.378 / 0.289, 새 GRU 0.223 / 0.213, 새 Mamba 0.217 / 0.212. 서버 추적 반복 안 실제 놓침: Kalman 대비 DanceTrack −16%, TMOT −10%. 새·옛 차이는 두 자료 모두 90% 구간이 0 아래.
- **왜 채택.** 사전 규칙("새 파일이 val-B 두 자료 모두에서 옛 파일보다 낮고 90% 구간이 0 아래")을 통과. GRU가 자동 선택, Mamba는 계산이 약 3배이면서 결과가 같아 선택지.
- **모르는 것.** 장치 25~30 fps 실카메라는 이때 측정 전. 자료 프레임 속도(5~20 fps)가 장치와 다름.

## 2. 11-16 GRU 고침 (우리 녹화에서 Kalman의 3배 오차)

- **왜.** 우리 카메라 녹화(정답 있는 TEST 14편, 놓침 238번)에서 11-15 GRU가 놓친 상자를 0.85배로 줄이고 키의 0.16 위로 올려 Kalman보다 오차가 3배였음(0.336 대 0.110). 서버 계산은 학습과 같음(val-B 다시 재면 TMOT 0.225, 학습 때 0.223).
- **원인.** 큰 것부터: (1) **화면 가장자리 입력 4개**가 공개 자료 카메라의 사람 배치(아래쪽 = 큰 사람)를 배웠고 우리 카메라는 작은 사람이 화면 아래쪽을 걷는다(놓침의 85%가 아래 입력 3 미만). 옛 파일에서 4개를 "멀리 = 5"로 두기만 해도 TEST 0.116. (2) 학습 자료 코드 잘못 2개(DanceTrack 회색 띠 줄로 가장자리를 재고, 화면에 잘린 정답에도 목표 생성): 이 둘만 고친 판 0.243(차이의 41%).
- **데이터·순서·설정.** 같은 자료, 가장자리 입력 없음(항상 5), 잘린 정답 뺌, 놓친 1장째에 그 프레임의 카메라 움직임 사용, 처음부터 30 epoch, val-A로 29 epoch 선택(선택 점수 0.2348). 같은 학습법.
- **손실 곡선.** 학습 손실 0.817 → 0.708, 검증 점수 0.281 → 0.236 — 옛 판(0.238)과 **거의 같음**. 즉 공개 자료 검증으로는 이 고장이 보이지 않았고 우리 녹화에서만 드러남.
- **결과(우리 TEST 14편).** Kalman 0.110 · 옛 GRU 0.336 · 새 GRU **0.122**(옛 대비 −0.214, 90% 구간 −0.310~−0.097). Kalman과 비교하면 +0.012([+0.004, +0.022]), 14편 중 10편에서 Kalman이 나음. 번호 유지 IDF1 74.1(Kalman) · 61.7(옛) · 74.7(새)로 Kalman과의 차이는 잡음 안. 관절이 안 보이는 64 px 이상 사람은 서버 규칙으로 Kalman을 써서 0.118.
- **왜 채택(그러나 Kalman을 이기지 못함).** 옛 파일의 3배 문제는 해결해 새 파일로 교체. 놓친 상자 숫자는 Kalman 쪽이 나아서 "GRU를 계속 자동으로 쓸지"는 사용자 결정으로 남김.
- **모르는 것.** 원인과 고침을 TEST로 찾았으므로(사전 등록 수정 기록은 남김) TEST 숫자는 독립 시험이 아님. 새로 정답을 단 녹화가 있어야 치우치지 않은 비교가 가능. 학습 목표 자체(관절 없는 큰 사람 목표가 머리~골반 상자로 만들어진 결함)는 다시 학습하지 않고 서버 규칙으로 막음.

## 3. 11-16 Mamba 재학습 (0.361 → 0.127)

- **왜.** 같은 원인이 Mamba에도 있었음(TEST 0.361, Kalman의 3배). 규칙으로 막은 판은 0.353.
- **설정.** GRU와 같은 수정(가장자리 입력 없음·잘린 정답 뺌·카메라 순서)으로 처음부터 30 epoch. 선택 epoch 20(선택 점수 0.2338), 학습 손실 0.830 → 0.703. 한 epoch가 GRU 28초 대 Mamba 164초.
- **결과.** TEST 0.361 → **0.127**(Kalman 0.110, GRU 0.122). 검증 점수는 GRU와 같은 수준(0.2346 대 0.2357).
- **왜 선택지로만.** GRU보다 낫지 않고 계산이 약 3배. 장치 속도 가까이서는 GRU와 차이 없음.
- **모르는 것.** 장치 속도 측정.

## 4. 11-16 GRU v3(`gru_near`) — 관절 절반 지움

- **왜.** 관절 없는 큰 사람·가까운 사람 오차(TEST 가까운 사람 0.175 대 Kalman 0.057) 해결 시도.
- **설정.** 학습 사람의 절반은 모든 관절 보임을 0으로, 관절 없는 검출은 몸 전체 상자를 목표로. 같은 학습법. 사전 등록 후 학습.
- **결과.** 가까운 사람 0.175 → 0.065(Kalman 0.057), 관절 없는 큰 사람 0.69배 → 0.95배, 전체 오차는 같음(0.122). 대신 실제 검출 놓침 0.190 → 0.206, TMOT val-B 0.206 → 0.231(옛 목표 정의 탓).
- **왜 선택지로만.** 더 나은 경우가 있어 고를 수 있게만 올림. 기본은 `gru_kpt` 유지.

## 5. 앞선 시도와 접은 것

- **PoseTrack18 관절 입력 판(11-14).** hidden 32/64/128 비교에서 관절을 넣은 GRU가 상자만 쓴 GRU보다 val-B 0.119 대 0.130(약 8% 좋음), 둘 다 Kalman 0.150보다 나음. 서버 GRUCell 68→64가 이 결과에서 옴. 11-15에 지움: 우리 검출기 입력에서 Kalman보다 나은 점이 없었음. 출처: 개인 실험 기록(m5_kpt_v2 결과 파일).
- **관절 없는 GRU·Mamba 40 epoch(11-14).** 야외 검증 0.1715·0.1726, 기본 0.1893 대비 약 9%. 사용자 요청으로 지움.
- **속도만 입력하는 GRU 기각.** 이 이름의 기록은 찾지 못함(기록 없음). 가장 가까운 기각은 상자 다듬기 GRU 1·2판(11-16 제거: 우리 카메라에서 단순한 변환표 + 크기 거르기를 못 이김)입니다.
